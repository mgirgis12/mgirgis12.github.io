When I first heard about coding standards, I thought they were mostly about making code look organized, like using the right spacing, indentation, and brackets. I did not really think they could help me become a better programmer. After using TypeScript, VS Code, and ESLint, I started to understand why coding standards are actually important.

## More Than Just Making Code Look Good

Before this class, when I was writing code, my main goal was to make it work. If I ran the program and got the correct answer, I usually thought I was done. I did not really pay attention to whether my code followed certain standards.

Now I understand that code should not only work, but it should also be easy to read and understand. This is especially important when working with other people. If everyone writes code differently, it can be harder to understand each other's work. Having coding standards makes the code more consistent.

I also think coding standards can help when learning a programming language. I am still getting used to TypeScript, so sometimes I make mistakes without noticing them. Having something point out those problems helps me see what I did wrong and learn from it.

## My Experience With ESLint

Using ESLint in VS Code has been useful, but sometimes it can also be annoying. When I see errors, I usually want to fix them so I can move on with my code. Some errors are easy to understand, but sometimes I have to look at the code again to figure out what is wrong.

Even though it can be annoying, I think ESLint is helpful because it shows me problems while I am working. Instead of finishing everything and finding problems later, I can fix them as I go.

This has been useful for me while learning TypeScript because I am still learning the syntax and different ways to write things. When ESLint shows a problem, it gives me an idea of where I should look.

## Learning From Errors

One thing I have noticed while programming is that a very small mistake can stop the code from working correctly. Sometimes it is just a missing bracket, a spelling mistake, or something in the wrong place.

When that happens, finding the problem can take me some time. Tools like ESLint make that easier because they can show me where there might be a problem. I still have to understand the error and figure out how to fix it, but at least I know where to start.

I think this also helps me learn. If I keep making the same mistake and fixing it, eventually I start remembering the correct way to do it. That is one reason I think coding standards can actually help someone learn a programming language.

## What I Think Now

I used to think coding standards were mostly about making code look nice. Now I think there is more to it. They can make code easier to read, help people work together, and help catch mistakes.

I still care the most about getting my program to work, but I am starting to understand that writing clean code is also important. Code might make sense to me when I first write it, but if I come back to it later, I want to be able to understand what I was doing.

After using ESLint, I would say it can be annoying and useful at the same time. I do not always like seeing more errors that I have to fix, but fixing them helps me understand what I am doing wrong. I think as I get more experience, following coding standards will start to feel more normal.
